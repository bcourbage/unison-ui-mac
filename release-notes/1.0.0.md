# Unison UI for macOS 1.0.0

Version 1.0.0 is the first release to state what stays stable. It adds no new kind
of synchronization. Instead, it settles the parts you build on, makes the app
clearer in the places where it used to leave you guessing, and fixes one way that
deleting a profile could throw away another profile's synchronization history. Your
existing profiles and settings work as they did before, with no migration.

## What 1.0 commits to

Until a 2.0, the `unison` command keeps its documented behavior. `unison <profile>`
opens the app on that profile, or runs the text interface if you have saved that as
your default. `-ui text` runs the text interface, and `-path`, `-include` and
`-source` scope a session. A request to an app that is already running is served,
waits its turn, or is refused with a stated reason, as the manual describes.

Profiles and archives remain Unison's own files, kept in
`~/Library/Application Support/Unison`, so they stay interchangeable with
command-line Unison and with upstream's app. Your settings carry forward across
updates, updates keep arriving through the signed Sparkle feed, and the platform
stays macOS 15 or later on Apple Silicon.

The vendored engine patches, the internal bridge API and the Debug-only test hooks
are not part of this promise and can change in any release. Where something can go
wrong, there is a documented way back. The
[FAQ](https://bcourbage.github.io/unison-ui-mac/faq/#what-happens-if-the-update-signing-key-is-lost-or-compromised)
explains, for example, what happens if the update signing key is ever lost or
compromised.

## Fixed

Deleting a profile no longer discards another profile's synchronization history.
Unison names an archive by its root pair, so two profiles with the same roots share
one set of archive files. Deleting one of them with the default choices moved those
files to the Trash, and the other profile's next run then started from nothing,
which meant a file you had deleted on one side was copied back instead of being
deleted. Now the delete confirmation keeps the files whenever another profile uses
them, names that profile, and checks again under the archive lock before it moves
anything. It also keeps them when it cannot be sure, such as when another profile
has a missing include, a `rootalias`, or a symlinked root. Reset Archives likewise
names any profile that shares the archives it is about to reset.

## Changed

When the engine warns or fails, the app now shows the first line of its message and
keeps the complete text in a scrolling, selectable Details area with a Copy Details
button, so a long path is never cut off partway. Warnings offer Continue and Cancel,
and the restart notice that follows a fatal error states the recovery step instead
of repeating the error.

The Diff window is titled with the file's name, shows the two files being compared
beneath the header, and keeps the command line behind a Command… button. For the
standard `diff` command it reports "Differences found." instead of "Exited with
status 1". A pipeline or another diff command keeps the status it reported.

The Profiles window now explains an empty list. With no profiles it offers Create
Profile…, and when every profile is hidden it offers Manage Profiles…. Run stays
disabled until you select a profile, and long names are truncated in the middle with
the full name as a tooltip. In the profile editor, a search with no matches says so
and offers Clear Search, the profile name is checked as you type with the reason
shown under the field and Save disabled until it is valid, and Check Remote Command
tells you up front that a new profile must be saved first.

A few smaller wording fixes round this out. The reconcile summary says "1 item" and
"1 conflict", help examples show as code instead of with backticks, and Archive
Maintenance describes exactly what it can remove and says "No cleanup candidates
were found." when there is nothing. Long Command Line setup paths are truncated in
the middle, with the full path as a tooltip.
