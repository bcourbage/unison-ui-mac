# Unison UI for macOS 1.0.0

Version 1.0.0 is the first release that states what stays stable. It adds no new
synchronization feature. It commits to the parts you build on, makes the app
explain itself better in the places where it used to leave you guessing, and fixes
one way that deleting a profile could discard another profile's synchronization
history. Existing profiles and settings continue to work without migration.

## What 1.0 commits to

Until a 2.0, these stay stable:

- **The `unison` command.** `unison <profile>` opens the app on that profile, or
  runs the text interface if that is your saved default. `-ui text` runs the text
  interface. `-path`, `-include` and `-source` scope a session. A request to a
  running app is served, waits, or is refused with a stated reason, as the manual
  describes.
- **Profiles and archives.** Profiles are Unison's own `.prf` files and archives
  are Unison's own, in `~/Library/Application Support/Unison`, so they stay
  interchangeable with command-line Unison and with upstream's app.
- **Settings and updates.** Saved settings carry forward across updates, and
  updates keep arriving through the signed Sparkle feed.
- **Platform.** macOS 15 or later on Apple Silicon.

The vendored engine patches, the internal bridge API and the Debug-only test hooks
are not part of this promise and may change in any release. Known failure modes
have a documented recovery. The
[FAQ](https://bcourbage.github.io/unison-ui-mac/faq/#what-happens-if-the-update-signing-key-is-lost-or-compromised)
explains what happens if the update signing key is ever lost or compromised.

## Fixed

- **Deleting a profile no longer discards another profile's synchronization
  history.** Unison names an archive by its root pair, so two profiles with the
  same roots share one set of archive files. Deleting one of them with the default
  choices moved those files to the Trash, and the other profile's next run then
  started from nothing: a file you had deleted on one side was copied back instead
  of being deleted. The delete confirmation now keeps the files when another
  profile uses them, names that profile, and checks again under the archive lock
  before it moves anything. It also keeps them when it cannot tell, for example
  when another profile has a missing include, a `rootalias`, or a symlinked root.
  Reset Archives names any profile that shares the archives it is about to reset.

## Changed

- **Engine warnings and errors are readable and complete.** A warning from the
  engine shows its first line and keeps the full text in a scrolling, selectable
  Details area with a Copy Details button, and its buttons are Continue and
  Cancel. A fatal error is shown the same way. The restart notice that follows no
  longer repeats the error cut off in the middle of a path: it states the recovery
  step and keeps the complete error in Details. Error text is no longer shortened
  on the way to these notices.
- **The Diff window names the file and reads the result.** Its title is the file's
  name, the two compared files appear beneath the header, and the command line sits
  behind a Command… button. For the standard `diff` command, the exit status reads
  "Differences found." instead of "Exited with status 1". A pipeline or another
  diff command keeps the status it reported.
- **The Profiles window explains an empty list.** With no profiles it shows "No
  profiles yet" and Create Profile…. With every profile hidden it shows "All
  profiles are hidden" and Manage Profiles…. Run stays disabled until a profile is
  selected, and long profile names are truncated in the middle with the full name
  as a tooltip.
- **The profile editor checks as you work.** A search with no matches says so and
  offers Clear Search. The profile name is validated as you type, and Save stays
  disabled until the name is valid, with the reason shown under the field. For a
  profile that has not been saved yet, Check Remote Command is disabled and says the
  profile must be saved first.
- **Smaller wording fixes.** The reconcile summary says "1 item" and "1 conflict".
  Examples in the Ignore and Advanced help show as code instead of with backticks.
  Archive Maintenance describes exactly what it can remove and says "No cleanup
  candidates were found." when there is nothing. The Command Line setup paths are
  truncated in the middle, with the full path as a tooltip.

## Added

- **Help ▸ Star on GitHub** opens the project page, next to Donate, and the About
  panel gains one linked sentence noting that a star helps others find the project.
