# Unison UI for macOS 1.0.1

Version 1.0.1 is a maintenance release. It makes opening a profile, retrying after an
error and recovering archives behave consistently when a command-line request arrives
at the same moment, and it keeps the protection around archives held by an interrupted
operation in force until a profile actually opens. Existing profiles and settings
continue to work without migration. Requires macOS 15 or later on Apple Silicon.

## Fixed

- **A command-line request no longer disturbs a password prompt.** If you ran
  `unison <profile>` while a password, passphrase or host-key prompt was waiting, the
  app used to close the window the prompt belongs to and report success without
  opening anything. It now refuses the request with a message, and the prompt stays
  where it is until you answer or cancel it.
- **Profiles blocked by an interrupted operation stay blocked until they open.** The
  app checked this only when a request was made. A profile queued behind another
  session, or waiting on your answer to a synchronization decision, could still open
  after its roots changed to overlap a held archive. The check now runs again just
  before the profile opens. A refused open returns to the profile picker with a
  notice, and a synchronization that is running is left alone.
  This now includes a profile that has a remote (`ssh://` or `socket://`) root next
  to a local one. The app cannot tell which archives such a profile uses until it
  connects, so it stays blocked while any interrupted operation holds archives, and
  it says why.
- **Rescan Ignoring Archives acts on the session you confirmed it for.** If a
  command-line request replaced that session while the confirmation was open,
  confirming used to close the replacement and reopen the older profile.
- **Recovery keeps the options a session was opened with.** Retry Ignoring Archives,
  Delete Orphans and Retry, and Rescan Ignoring Archives used to reopen the profile
  without options such as `-path`, so the recovery scan could cover the whole profile.
  They now keep the options, and later reconnects use them too.
- **Retry Ignoring Archives no longer edits your profile file.** The setting applies
  to that one reopen. It also takes effect when the session was opened with
  `-ignorearchives=false`, and a recovery you cancel leaves nothing behind.
- **Reset Archives, Delete Profile and the open check follow includes.** A profile
  whose roots live in an included file no longer looks like it has none. When the
  includes cannot be resolved, the app keeps archives in place and blocks opening
  while interrupted operations hold archives. A profile file without an extension
  that has the same name counts as another owner of the archives.
- **The profile picker has a minimum size,** and a saved window size that is too small
  is raised when the picker is restored.

## Under the hood

The app now loads the held-archive state before it answers command-line requests, and
a recovery reopen checks the held-archive state first. Unused code was removed and
several large source files were split, with no change in behavior.
